## 1. 비기능 요구사항

| ID | 요구사항 | 인수 조건 | MVP | 상태 |
|---|---|---|---|---|
| REQ-NF-01 | 오프라인은 운동 세션만 지원한다 | 네트워크가 없을 때 운동 세션은 Room에 저장되고 복구 후 업로드된다. 식사·홈·코칭·Growth는 마지막 응답을 보여주고 쓰기는 안내 메시지로 막는다. 홈의 오늘 칼로리는 마지막 동기화 시각을 함께 표시한다 | 1 | 제안 |
| REQ-NF-02 | 모든 업무 API는 인증을 요구한다 | 공개 경로(`/actuator/health`, `/v3/api-docs/**`, `/swagger-ui/**`, 로그인·토큰 재발급)를 제외한 `/api/v1/**`는 토큰 없이 401 `UNAUTHORIZED`. 다른 회원의 리소스 접근은 403 또는 404 (가정: 존재 노출 방지를 위해 404) | 1 | 제안 |
| REQ-NF-03 | 응답은 ApiResponse로 포장한다 | 성공·실패·401·403·404·500 모두 `success`·`data`·`error{code,message}` 모양. 검증 실패는 400과 `필드: 메시지` | 1 | 제안 |
| REQ-NF-04 | 내부 오류 정보를 노출하지 않는다 | 처리되지 않은 예외는 500 `INTERNAL_ERROR`와 고정 메시지. 스택·SQL·내부 경로가 응답에 없다 | 1 | 제안 |
| REQ-NF-05 | 응답 시간 (가정) | 조회 API p95 500ms 이하, 쓰기 API p95 1초 이하(인식 제외). 사진 인식은 10초 안에 결과 또는 폴백 안내. 수치는 설정값으로 두고 데모 환경에서 측정한다 | 2 | 제안 |
| REQ-NF-06 | 시간대는 Asia/Seoul로 통일한다 (가정) | "오늘"·DailyGoal·Streak 판정은 Asia/Seoul 자정 기준. API의 시각은 오프셋이 있는 ISO-8601. 사용자별 시간대는 지원하지 않는다 | 1 | 제안 |
| REQ-NF-07 | UI 언어는 한국어다 | 모든 화면 문구·오류 안내가 한국어. 다국어는 범위 밖 | 1 | 제안 |
| REQ-NF-08 | 핵심 여정 탭 수 상한을 지킨다 | 앱 실행 → 운동 시작 3탭 이하, 세트 완료 1탭(워치), 무게 변경 2탭 이하, 촬영 → 식사 저장 3탭 이하. 이전 기록은 세트 화면에 항상 보인다 | 1·2 | 제안 |
| REQ-NF-09 | 예측과 수정 데이터는 삭제하지 않는다 | meal_prediction·meal_correction은 식사가 삭제돼도 남는다. 회원 비활성화 후 처리는 미결 | 1 | 제안 |
| REQ-NF-10 | 웹·Android는 생성 타입만 쓴다 | `generated/` 밖에 API 요청·응답 타입을 손으로 만들지 않는다. 계약 변경 MR은 소비 표면 담당 리뷰를 받는다 | 1 | 제안 |
| REQ-NF-11 | Secret은 저장소와 클라이언트 빌드에 없다 | `.env.example`에는 이름만. `VITE_` 변수와 Android 빌드에 비밀 값이 들어가지 않는다 | 1 | 제안 |
| REQ-NF-12 | 이벤트 핸들러는 멱등하고 원 트랜잭션을 깨지 않는다 | 같은 이벤트를 두 번 받아도 결과가 한 번과 같다. 핸들러 실패가 발행 측 응답을 실패로 만들지 않는다 | 1 | 제안 |
| REQ-NF-13 | 업무 데이터는 Spring만 쓴다 | FastAPI·ml은 업무 DB에 쓰지 않는다. 모델·지표는 MLflow에 둔다 | 3 | 제안 |
| REQ-NF-14 | 서버 → 클라이언트 푸시는 FCM, 스트리밍은 RAG 채팅 SSE만 | WebSocket을 쓰지 않는다. FCM 페이로드는 ID만 담고 클라이언트가 REST로 재조회한다 | 3 | 제안 |

## 2. 홈 화면 (MVP-1)

홈은 "지금 할 일 하나와 큰 버튼 하나"다(기획서 2장). 데이터는 Growth와 Coaching이 제공하고 Meal 촬영으로 진입한다.

| ID | 요구사항 | 인수 조건 | MVP | 상태 |
|---|---|---|---|---|
| REQ-HOME-01 | 냠냠이 외형과 레벨·XP를 보여준다 | Growth 조회 API의 `nyamStage`·`level`·`xp`·다음 레벨까지 남은 XP를 표시한다 | 1 | 제안 |
| REQ-HOME-02 | Streak을 보여준다 | Growth의 `streakDays`. 0이면 "오늘 시작" 류의 문구 (가정) | 1 | 제안 |
| REQ-HOME-03 | 오늘 칼로리를 섭취·목표·잔여로 보여준다 | Coaching의 오늘 요약 API. 온보딩 직후 Program이 아직 없으면 목표를 "계산 중"으로 표시하고 오류로 보이지 않는다 | 1 | 제안 |
| REQ-HOME-04 | 촬영은 홈에서 1탭이다 | 촬영 버튼이 홈 첫 화면에 있고 누르면 바로 카메라 | 1 | 제안 |
| REQ-HOME-05 | 식사 저장 후 홈이 즉시 갱신된다 | 저장 화면에서 돌아오면 Nyam 반응, XP 증가, 오늘 칼로리가 새 값으로 보인다. 이벤트 처리가 비동기이므로 홈은 복귀 시 재조회하고, 1초 안에 반영되지 않으면 당겨서 새로고침으로 받는다 (가정) | 1 | 제안 |
| REQ-HOME-06 | 오프라인이면 마지막 값과 동기화 시각을 보여준다 | 네트워크 없이 열면 캐시 값과 "HH:mm 기준" 표시. 촬영 버튼은 비활성 안내 | 1 | 제안 |
