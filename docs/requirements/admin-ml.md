## 1. 범위

- 포함: 관리자 접근 제어, 예측 vs 수정 쌍 검수(승인·반려), 검수 현황, 승인분으로 데이터셋 빌드, 학습·오프라인 평가·품질 게이트, MLflow 등록과 Production 승격, 추론 서버 모델 교체, 관리자 웹의 모델 버전·지표 조회
- 제외: 자동 재학습·A/B 테스트·drift 모니터링(기획서 7장), Food DB 관리자 CRUD(기획서 7장), 회원 관리·통계 대시보드, Kubeflow·Airflow 같은 파이프라인 도구(ADR-0011)
- 관리자 웹은 화면 3개 이내다(ADR-0010). (가정) 검수 목록, 검수 상세, 모델 버전·지표.
- 이 명세의 목표는 기획서 J3 "사용자의 수정 한 번이 다음 모델을 만든다"를 7주차 데모에서 한 바퀴 실제로 돌리는 것이다.

## 2. 기능 요구사항

### 2.1 접근

| ID | 요구사항 | 인수 조건 | MVP | 상태 |
|---|---|---|---|---|
| REQ-ADMIN-01 | 관리자만 관리자 기능을 쓴다 | 관리자 API는 `ADMIN` 역할만 호출할 수 있고, USER는 403 `FORBIDDEN`. 웹 `/admin/*`는 역할 가드로 막는다. 역할 부여 방식은 [REQ-MEMBER-13](./member.md)을 따른다 | 3 | 제안 |
| REQ-ADMIN-02 | 검수 화면에 회원 식별 정보를 보이지 않는다 | 검수 목록·상세에 닉네임·이메일·memberId를 표시하지 않는다 (가정). 관리자는 사진·예측·수정값·시각만 본다 | 3 | 제안 |

### 2.2 검수

| ID | 요구사항 | 인수 조건 | MVP | 상태 |
|---|---|---|---|---|
| REQ-ADMIN-03 | 검수 대기 목록을 본다 | 검수 결과가 없는 예측·수정 쌍을 최신순으로 페이지 단위(가정: 20건)로 돌려준다. 기간, 수정 여부(`is_changed`), 음식명, 신뢰도 구간, 모델 버전으로 거를 수 있다. 기본 필터는 수정된 쌍만이다 (가정) | 3 | 제안 |
| REQ-ADMIN-04 | 쌍 하나를 비교해 본다 | 상세에 사진, 모델 예측(후보·신뢰도·모델 이름과 버전), 사용자 확정값(음식명·양), 기록 시각이 있다. 식사가 삭제된 쌍도 볼 수 있다(REQ-NF-09) | 3 | 제안 |
| REQ-ADMIN-05 | 승인하거나 반려한다 | 승인·반려 결과가 검수자 ID·시각과 함께 저장되고 쌍 하나에 결과 하나다. 반려는 사유가 필수다 (가정: 사진 불량·확정값 오류·음식 아님·기타). 이미 검수한 쌍을 다시 검수하면 결과를 갱신한다 (가정) | 3 | 제안 |
| REQ-ADMIN-06 | 여러 건을 한 번에 승인한다 | 목록에서 여러 쌍을 골라 일괄 승인할 수 있다 (가정: 한 번에 최대 50건). 일부가 이미 검수됐으면 그 건만 건너뛰고 결과에 건너뛴 수를 돌려준다 | 3 | 제안 |
| REQ-ADMIN-07 | 수정하지 않은 쌍도 검수할 수 있다 | `is_changed=false` 쌍은 "모델이 맞혔다"는 확인 데이터다. 필터를 바꾸면 목록에 나오고 같은 방식으로 승인·반려한다. 데이터셋 포함 여부는 미결(5장) | 3 | 제안 |
| REQ-ADMIN-08 | 검수 현황을 본다 | 대기·승인·반려 건수와 기간별 수정률(수정된 쌍 / 전체 쌍)을 돌려준다. 모델 버전별로 나눠 볼 수 있다 | 3 | 제안 |

### 2.3 데이터셋 · 학습 · 평가 (ml/)

| ID | 요구사항 | 인수 조건 | MVP | 상태 |
|---|---|---|---|---|
| REQ-ADMIN-09 | 승인분으로 데이터셋을 만든다 | 데이터셋 빌드는 `APPROVED` 쌍만 업무 DB에서 읽기 전용으로 가져온다. 결과에 버전 태그가 붙고, 건수·음식 클래스 분포·원천 기간·제외 건수를 MLflow에 기록한다. 같은 입력이면 같은 데이터셋이 나온다 | 3 | 제안 |
| REQ-ADMIN-10 | 학습 기록을 남긴다 | 학습은 사람이 실행한다 (가정: 스크립트 수동 실행). 실행마다 MLflow run에 데이터셋 버전, 베이스 모델, 하이퍼파라미터, 학습 지표, 모델 아티팩트를 남긴다 | 3 | 제안 |
| REQ-ADMIN-11 | 오프라인 평가를 한다 | 학습에 쓰지 않은 고정 평가셋 (가정: 데이터셋 버전마다 분리한 holdout)으로 top-1 정확도와 혼동 상위 쌍(가정: 10쌍)을 계산해 같은 run에 기록한다. 현재 Production 모델도 같은 평가셋으로 다시 평가한다 | 3 | 제안 |
| REQ-ADMIN-12 | 품질 게이트를 통과한 모델만 등록한다 | 새 모델의 top-1 정확도가 같은 평가셋에서 현재 Production 이상일 때만 레지스트리에 Staging(또는 해당 alias)으로 등록한다. 미달이면 등록하지 않고 run에 실패 사유를 남긴다. Production이 없으면 첫 모델은 통과로 본다 | 3 | 제안 |
| REQ-ADMIN-13 | Production 승격은 사람이 승인한다 | Staging 모델을 Production으로 올리는 것은 수동이다. 승격한 사람과 시각이 레지스트리에 남는다. 승격 주체(스크립트 / 관리자 웹)는 미결(5장) | 3 | 제안 |
| REQ-ADMIN-14 | 업무 DB에 쓰지 않는다 | `ml/`과 `ai/`는 업무 테이블에 쓰지 않는다. 데이터셋·모델·지표는 MLflow에만 남는다(REQ-NF-13) | 3 | 제안 |

### 2.4 추론 교체와 조회

| ID | 요구사항 | 인수 조건 | MVP | 상태 |
|---|---|---|---|---|
| REQ-ADMIN-15 | 추론 서버가 Production 모델을 쓴다 | `ai/`는 기동 시 레지스트리의 Production 모델을 받는다. 레지스트리에 닿지 못하면 마지막 로컬 캐시로 기동하고, 캐시도 없으면 모델 없이 기동해 인식 요청에 503을 돌려준다(Meal은 검색 폴백). 새 버전 반영 방식(재기동 / 무중단 재로드)은 미결 | 3 | 제안 |
| REQ-ADMIN-16 | 어떤 모델이 예측했는지 남긴다 | 모든 인식 결과에 모델 이름과 버전이 있고 Meal이 `meal_prediction.model_version`에 저장한다. 외부 API를 쓰면 그 식별자를 버전으로 쓴다 | 3 | 제안 |
| REQ-ADMIN-17 | 관리자 웹에서 모델 버전과 지표를 본다 | 등록된 모델 버전 목록에 버전, 스테이지(또는 alias), 등록 시각, 데이터셋 버전, top-1 정확도가 있고, 현재 서빙 중인 버전이 표시된다. Spring이 MLflow REST를 프록시하고 웹은 MLflow에 직접 붙지 않는다. MLflow가 응답하지 않으면 503 `ADMIN_MLFLOW_UNAVAILABLE` (가정) | 3 | 제안 |
| REQ-ADMIN-18 | 버전별 실사용 수정률을 비교한다 | 모델 버전별 예측 건수와 수정률을 나란히 보여준다(REQ-ADMIN-08 재사용). 새 버전 배포 후 수정률이 내려갔는지를 데모에서 보여주는 근거다 | 3 | 제안 |

## 3. 정책

- 검수 결과(`correction_review`)는 Spring만 쓴다. 관리자 웹은 Spring API를 거친다.
- 승인된 쌍만 학습 데이터가 된다. 반려된 쌍과 검수 대기 쌍은 데이터셋에 들어가지 않는다.
- 데이터셋 원본·모델 파일은 git에 커밋하지 않는다(ml/README).
- 품질 게이트 비교는 항상 같은 평가셋에서 한다. 평가셋이 다르면 비교 결과를 게이트 근거로 쓰지 않는다.
- Vision 베이스 모델이 외부 API로 정해져도 예측·수정 적재, 검수, 평가 루프는 같다(ADR-0011). 이때 학습 대상은 외부 API 뒤의 자체 분류기다 (가정).
- 데모용 1회전은 소규모 데이터셋으로 한 번만 돈다(기획서 8장). 자동 재학습은 하지 않는다.

| 레지스트리 표기 | Staging·Production 스테이지 또는 `@staging`·`@production` alias | 미결 (기획서 9장) |

## 5. 이벤트와 공개 조회

| 구분 | 이름 | 시점·용도 | 페이로드·반환 |
|---|---|---|---|
| 구독 | `MealCorrected` | 검수 대기 발생 | memberId, mealId, predictionId |
| 공개 조회 (Meal 제공) | 예측·수정 쌍 조회 (가정: `MealQueryService.getPredictionPairs`) | 검수 목록·상세, 수정률 | 사진 경로, 예측, 확정값, 모델 버전 DTO |

발행하는 이벤트는 없다. Admin은 Meal 테이블을 직접 읽지 않고 Meal의 공개 조회를 쓴다(ADR-0008). `ml/datasets`는 Spring 밖이라 업무 DB를 읽기 전용 계정으로 직접 읽는다(ADR-0011).
