# 요구사항 명세

제품이 각 상황에서 **어떻게 동작해야 하는지**를 검증할 수 있게 적는 문서다. 항목마다 인수 조건이 붙어 있어
harness 플랜의 인수 테스트와 MR 리뷰가 이 문서를 기준으로 삼는다. "왜 만드는지"는 [기획서](../renewal/plan.md)가,
"어떤 요청·응답인지"는 `contracts/openapi.json`이, "데이터가 어떻게 생겼는지"는 [ERD](../design/erd.md)가 답한다.

## 항목 규칙

- ID는 `REQ-<도메인>-<두 자리>`. 번호는 재사용하지 않는다. 비기능은 `REQ-NF-`, 홈 화면은 `REQ-HOME-`.
- 열은 ID · 요구사항 · 인수 조건 · MVP · 상태. 인수 조건은 입력과 기대 결과가 드러나게 쓴다. 오류는 HTTP 상태와 `ErrorCode` 이름으로 적는다.
- 상태는 `제안` → `확정` → `구현` → `폐기`. 폐기한 항목은 지우지 않고 상태만 바꾼다.
- `(가정)`은 작성자가 채운 초안값이다. 소유자가 확정하면 표기를 지운다. 값·임계치는 설정값 이름을 적고 숫자는 참고로만 둔다.
- 화면 레이아웃, 코드 구조, 엔드포인트 모양은 적지 않는다. 각각 디자인, 영역 `AGENTS.md`, OpenAPI가 맡는다.

## 갱신

- 이 폴더는 **현행 갱신** 문서다. 구현 MR이 동작을 바꾸면 같은 MR에서 항목을 고친다. 기획서는 바꾸지 않는다.
- 문서 변경은 Jira 업무 항목과 MR을 거친다. 다른 도메인에 영향을 주는 항목(이벤트, 공개 조회)은 상대 도메인 소유자를 리뷰어로 넣는다.
- harness 플랜의 "1. 기준 문서"에는 읽은 항목을 `REQ-MEAL-04`처럼 ID로 인용한다.
- 문서를 추가하면 위 표에 넣는다.
