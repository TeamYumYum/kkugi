|---|---|
| 상태 | 초안 |
| 적용 상황 | 3주차 MVP-1, 5주차 MVP-2, 7주차 MVP-3 데모와 8주차 최종 발표 |
| 소유 | 팀장(태그·진행), C(환경), 각 시연 담당 |

Git 컨벤션은 "데모 범위·DB 변경·롤백 확인을 태그 전에 팀 채널에 같은 항목으로 남긴다"고 정했다. 이 Runbook이 그 항목의 목록이다.

## 데모 범위

| 데모 | 태그 | 시연 | 표면 |
|---|---|---|---|
| MVP-1 | `demo/mvp1` | 소셜(또는 개발용) 로그인 → 온보딩 → 사진 식사 기록 → 홈(Nyam·Streak·오늘 칼로리·XP) | 폰 |
| MVP-2 | `demo/mvp2` | 루틴 생성 → 워치 Workout Mode 세트 기록 → 폰 완료 화면(볼륨·PR·XP·Streak) → AI 루틴 조정 → 칼로리 밸런스 | 워치 + 폰 |
| MVP-3 | `demo/mvp3` | 웹 대시보드 → FCM 알림 → MLOps 1회전(수정 적재 → 검수 → 평가 → 버전 → 추론 교체) → 주간 리포트 → 뱃지 | 웹 + 전체 |
| 최종 | `final` | 전체 여정 리허설 순서대로 | 전체 |

## D-2: 범위 동결

- [ ] 데모에 들어갈 MR이 모두 `main`에 병합됐다. 이후 병합은 `fix/`만.
- [ ] 데모 시나리오 대본을 한 장으로 적었다. 화면 순서, 누가 어느 기기를 드는지, 말할 한 줄.
- [ ] 데모 계정과 데이터 준비 방법을 정했다(가정: 시드 스크립트 또는 전날 수동 입력. 위치 미결).

## D-1: 태그·배포·리허설

1. **검증과 태그**. 개발 흐름 7장을 따른다. `main` 최신화 → 전체 검증 명령 통과 → 채널에 범위·DB 변경·롤백 방법 기록 → 팀장이 태그 Push.
2. **배포**. [배포 Runbook](./deploy.md) 전 단계. 스모크는 데모 시나리오 그대로.
3. **데모 데이터**. 데모 계정으로 로그인해 Program이 있고 홈이 채워져 있는지 본다. MVP-2는 데모 루틴이 **워치에 미리 내려가 있는지**(ADR-0002 루틴 사전 캐시) 확인한다. MVP-3는 검수 대기 수정 데이터와 학습 1회전 결과가 MLflow에 있는지 본다.
4. **AI 모드 결정**. `CLAUDE_MOCK`을 실호출(`false`)로 할지 정한다. 실호출이면 GMS 키·쿼터·응답 시간을 리허설에서 확인하고, 불안하면 mock으로 간다. Vision 모델이 로드됐는지 `GET /ai/health`로 본다.
5. **기기**. 폰·워치 충전 100%, 페어링 확인, 알림 방해 금지(데모 중 다른 알림 차단, 단 FCM 데모는 예외), 화면 자동 꺼짐 끔, 폰 화면 미러링 도구 연결.
6. **네트워크**. 발표장 Wi-Fi와 핫스팟 두 경로. 서버 주소가 어느 쪽에서도 열리는지 확인. MVP-2 워치 구간은 **네트워크 없이** 진행되는 것이 강점이므로 비행기 모드 시연 여부를 정한다.
7. **리허설**. 대본대로 처음부터 끝까지 1회. 막힌 곳과 소요 시간을 기록. 막힌 곳은 `fix/`로 고치고 새 태그(태그는 옮기지 않는다).
8. **백업 플랜**. 전 구간 화면 녹화 영상을 만들어 발표 노트북에 둔다. 서버가 죽어도 발표는 이어진다.

## 당일: 시작 30분 전

- [ ] 배포 Runbook 7단계 health 전부 통과.
- [ ] 데모 계정 로그인 1회, 홈 로딩 확인.
- [ ] 워치 → 폰 연결 상태, 워치에 오늘 루틴 표시(MVP-2).
- [ ] 웹 대시보드 로그인, 관리자 화면 진입(MVP-3).
- [ ] 백업 영상 재생 확인.
- [ ] 운영자 1명이 서버 로그를 보는 터미널을 열어 둔다(`docker compose logs -f backend ai`).

## 데모 중 장애

| 증상 | 조치 | 발표자 |
|---|---|---|
| API 5xx 연속 | 운영자가 `docker compose restart backend`. 30초 안에 안 돌아오면 롤백 판단 | 백업 영상으로 전환 |
| 인식 실패·지연 | 검색 입력 폴백으로 시연을 계속한다(제품은 수정 UX로 성립, 기획서 8장) | 폴백 경로 설명 |
| 워치 ↔ 폰 동기화 안 됨 | 폰에서 직접 세션 기록으로 전환(세션 소유권 단일 원칙 설명) | 계속 |
| FCM 미도달 | 알림 센터 대신 서버 로그로 발송 사실을 보여준다 | 계속 |
| 네트워크 단절 | 핫스팟 전환. 워치 세션 구간은 영향 없음 | 계속 |

롤백은 데모 중에는 하지 않는다. 데모가 끝난 뒤 [롤백 Runbook](./rollback.md)으로 판단한다.
