# Runbook

특정 작업이나 상황에서 **그대로 따라 할 수 있는 실행 절차**다. 각 Runbook은 적용 상황, 사전 조건, 필요한 권한, 절차,
중단 조건, 완료 확인, 복구·연락 순서로 쓴다. 규칙은 정의하지 않고 규칙 문서를 링크한다.

| Runbook | 적용 상황 | 소유 | 상태 |
|---|---|---|---|
| [배포](./deploy.md) | `main`의 태그 커밋을 서버에 올릴 때 | C | 초안. 배포 환경 확정 전이라 compose 단일 호스트 기준 |
| [롤백](./rollback.md) | 배포 후 health·스모크 실패, 데모 중 치명 결함 | C·D | 초안 |
| [데모](./demo.md) | 3·5·7주차 데모와 8주차 최종 발표 전날·당일 | 팀장·C | 초안 |
| 장애 대응(DB 접속 불가, FastAPI 다운, Redis 장애) | 운영 중 장애 | C·D·E | 배포 환경 확정 후 작성 |

- 배포 환경(서버·도메인·TLS)과 CI 자동 배포가 정해지면 세 Runbook의 `(가정)`을 지우고 명령을 실제 환경에 맞춘다.
- Runbook을 실행하면 결과를 팀 채널에 남긴다. 커밋·태그·시각·실행자·이상 여부.
- 실제 Secret 값은 Runbook에 쓰지 않는다([Secret 규칙](../../secret-environment-variables.md)).
