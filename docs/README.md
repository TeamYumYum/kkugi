# Documentation

프로젝트의 설계 및 협업 문서를 관리합니다.

## 문서 역할과 우선순위

규칙은 한 문서에만 정의하고 다른 문서는 링크로 참조합니다. 문서 종류별 역할은 다음과 같습니다.

| 종류 | 문서 | 역할 |
| --- | --- | --- |
| 기획 | 리뉴얼 기획서 | 누구의 어떤 문제를 풀고 제품이 어디로 가는지, 무엇을 누가 언제 만드는지의 합의본입니다. 합의를 보존하는 문서라 구현이 바뀌어도 고쳐 쓰지 않습니다 |
| 설계·계약 | 요구사항 명세, API 공통 규약, 논리 ERD, 물리 스키마 규칙, 이벤트 목록, ADR | 무엇을 만들지와 영역 간 계약을 정의합니다. 구현은 계약을 따르고, 계약을 바꿀 때는 문서를 먼저 수정합니다. ADR을 제외하면 현행에 맞춰 갱신하는 문서입니다 |
| 코드 규칙 | 영역별 개발 컨벤션 | 어떤 코드가 좋은 코드인지, 구현 시 지켜야 할 규칙을 정의합니다 |
| 협업 규칙 | Git 컨벤션, Secret 및 환경변수 관리 규칙, 역할 분배 | 브랜치·커밋·MR, 설정과 인증정보, 담당 영역처럼 팀이 함께 지키는 규칙을 정의합니다 |
| 병렬 작업 조직 | AI 병렬 작업 및 충돌 방지 규칙 | 여러 작업자와 AI가 같은 저장소에서 동시에 작업할 때의 작업 공간 분리, 충돌 위험 분류, 합의가 필요한 변경을 정의합니다 |
| AI 작업 절차 | 루트 `AGENTS.md`, 작업 대상 영역의 `AGENTS.md` | 루트 공통 절차와 변경 경로에 해당하는 영역 지침만 적용합니다. 각 `CLAUDE.md`는 같은 디렉터리의 `AGENTS.md`를 가리킵니다 |
| 산출물 양식 | 플랜·리뷰 [템플릿](./templates/) | 영역 `AGENTS.md`가 요구하는 산출물의 양식만 제공합니다. 규칙을 새로 정의하지 않습니다 |
| 절차 안내 | Jira-GitLab 개발 흐름 | 규칙을 실제로 수행하는 순서와 도구 사용법을 설명합니다 |
| 운영 절차 | Runbook, 체크리스트 | 특정 작업·상황에서 따라 할 실행 절차와 완료 확인을 정의합니다. 규칙을 새로 정의하지 않고 규칙 문서를 링크합니다 |
| 실행 안내 | 각 디렉터리의 `README.md` | 실행, 빌드, 환경 변수, 배포, 상태 확인을 안내합니다. 규칙을 새로 정의하지 않고 규칙 문서를 링크합니다 |

같은 수준의 문서가 서로 다르게 말하면 규칙 문서(코드 규칙, 협업 규칙, AI 작업 절차)가 안내 문서(실행 안내, 절차 안내, 운영 절차)보다 우선합니다.
설계·계약 문서와 사용자 지시, 요구사항 사이의 우선순위는 루트 `AGENTS.md` 1장을 따릅니다.
